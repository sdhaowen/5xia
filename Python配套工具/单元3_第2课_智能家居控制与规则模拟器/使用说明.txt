==============================================
 智能家居控制与规则模拟器 · 使用说明
==============================================
配套教材:清华大学出版社《信息科技》五年级下册
          第3单元 第2课《智能家居背后的技术原理——小程序控制开关灯》(教材 P91—101)
适用对象:小学五年级学生与信息科技教师
运行环境:Windows 7/10/11,安装 Python 3.8 及以上(自带 Tkinter),
          完全离线运行,不需要联网,不需要安装任何第三方库。
特别说明:界面上的小程序「我家小屋」是虚构的教学界面,
          不是任何真实平台,不需要注册账号,不采集任何真实数据。

----------------------------------------------
一、这个工具是做什么的?
----------------------------------------------
它在电脑上完整模拟"用手机小程序远程控制家里的灯"的过程:
  左边是一部虚拟手机,上面是小程序「我家小屋」,有客厅灯、卧室灯两个按钮;
  中间下方是消息链路——每条开关灯指令都要经过
      小程序 → 网络 → 物联网平台 → 控制器
  四个节点逐跳传输,你能亲眼看到橙色小圆点一站一站地移动;
  右边是家里的客厅和卧室,控制器执行指令后灯才真的亮/灭(有光效);
  灯变化后还会有一条绿色的"状态回传"消息按原路走回小程序,
  小程序按钮上的图标要等回传到达才会更新。
你还可以制造网络延迟、丢包、断网,切换访客账号体验权限拒绝,
关闭防抖体验连点让灯闪烁,并给平台勾选"天黑自动开灯"等自动化规则。

----------------------------------------------
二、运行方法
----------------------------------------------
方法1(推荐,双击运行):
  1. 确认电脑已安装 Python(见"常见问题"第1条);
  2. 双击「智能家居控制与规则模拟器.py」即可打开窗口。
     若双击打开的是记事本,请右键该文件 → 打开方式 →
     选择「Python」(或 Python Launcher)。

方法2(命令行运行):
  1. 按 Win + R,输入 cmd,回车打开命令提示符;
  2. 输入(注意路径里有中文,建议直接把文件拖进命令行窗口):
         python "智能家居控制与规则模拟器.py"
     若提示找不到 python,可尝试输入 py 代替 python。

----------------------------------------------
三、界面分区说明
----------------------------------------------
① 场景区(左上,一整块画布)
   - 手机小程序(左):「我家小屋」上有客厅灯、卧室灯两个大按钮,
     按钮上的小灯图标 = "小程序认为"的灯状态(黄=开,灰=关);
     指令在路上时按钮下方显示"指令发送中…",被平台拒绝时显示"✋被拒";
   - 消息链路(下方):小程序→网络→物联网平台→控制器 四个节点。
     橙色圆点 = 开关灯指令(下行),绿色圆点 = 状态回传(上行),
     灰色 = 断网排队中,红色 = 丢失/过期/被拒。
     只有"网络段"(小程序↔网络↔平台)会丢包和断网,
     平台↔控制器是家里的可靠连接;
   - 房间与灯(右):客厅、卧室各一盏吊灯,亮时有黄色光晕,
     这才是灯的"真实状态"。天黑(光照<30%)且灯灭时房间会变暗。
     当手机图标和灯的真实状态不一样时,房间里会出现红色提醒
     「⚠ 与手机图标不一致!」——这多半是状态回传丢了;
   - 中间面板:图例、太阳/月亮(环境光照)、网络与账号状态、
     "最近一条指令的生命周期"(发送→送达→执行→回传→图标更新)。

② 参数区(右上):
   - 网络延迟 / 丢包率 / 环境光照 三个滑块;
   - 「断网」「防抖」两个开关;
   - 「家人 / 访客」账号切换(访客没有开灯权限)。

③ 规则区(右中):三条可勾选的自动化规则,存放在物联网平台上:
   - 天黑自动开客厅灯(光照 < 30%);
   - 天亮自动关所有灯(光照 > 70%);
   - 长亮节能:一盏灯连续亮 60 个周期自动关掉。

④ 运行控制区(右中):开始 / 暂停 / 单步 / 重置。
   注意:开关灯不在这里!要直接点手机上的小程序按钮。

⑤ 状态与日志区(下方):
   - 状态栏:当前周期、两盏灯的真实状态与手机图标、网络、账号、光照;
   - 滚动日志:每条指令的完整生命周期(发送→送达→执行→回传→
     图标更新 / 被拒 / 丢失 / 排队 / 过期)都有记录,
     不同类型用不同颜色显示。

⑥ 结果区(右下):
   - 统计:发出指令数 / 成功执行 / 被平台拒绝 / 丢失过期 / 规则触发数;
   - 四个按钮:导出日志CSV / 导出小结TXT / 导入示例场景 / 帮助。

----------------------------------------------
四、每个按钮与参数的含义
----------------------------------------------
▶ 开始         让模拟时间流动,每 0.4 秒推进一个周期,消息每周期走一跳。
⏸ 暂停         暂停时间流动,所有状态保持不变。
⏭ 单步         先暂停,再只推进一个周期。想看清指令怎么一跳一跳走,
               就连续点它。
🔄 重置         灯全部熄灭、在途消息清空、统计清零;
               参数滑块、规则勾选和日志保留,方便对比实验。
手机上的灯按钮  点一下 = 在小程序里发出一条开(或关)灯指令。
               指令内容由"小程序当前认为的状态"决定:图标是关就发"开"。
🔌 断网         勾上后,网络段的消息全部排队等待(圆点变灰);
               取消勾选恢复网络,排队超过 25 个周期的指令会"过期作废"。
🛡 防抖         勾上后,同一盏灯 3 个周期内的重复点击会被小程序忽略,
               防止手抖连点;关掉它再快速连点,会发出开/关/开…
               一串指令,灯就会来回闪烁!
登录账号        家人 = 全部权限;访客 = 没有开灯权限,开灯指令走到
               物联网平台就会被拒绝,并回传"被拒"通知(访客可以关灯)。
网络延迟(0~3档) 消息每走一跳额外等待的周期数。0=正常,3=特别卡。
丢包率(0~80%)  消息经过"网络段"时丢失的概率。指令丢了灯不会动;
               状态回传丢了,灯动了但手机图标不更新。
环境光照(0~100%) 模拟白天黑夜:低于 30% 算天黑,高于 70% 算天亮,
               配合规则区的自动化规则使用。
三条规则勾选    见上文"③规则区"。规则由平台发出指令(不经过手机),
               所以就算手机断网,规则照样能工作。
📥 导出日志CSV  把全部日志存成 CSV 表格(Excel 可直接打开),
               文件保存在本程序所在文件夹,文件名自动加时间戳。
📄 导出小结TXT  生成实验小结:参数、统计、最近日志和思考题,
               可打印后手写完成,当作教材"项目日志"。
📂 导入示例场景 读入「示例数据_家居场景.json」,内含三组场景:
               教材示例:客厅一盏灯 / 网络糟糕的雨天 / 天黑自动开灯规则。
❓ 帮助         弹出快速帮助窗口。

----------------------------------------------
五、一条指令的生命周期(重点!)
----------------------------------------------
    发送(小程序)→ 送达(控制器)→ 执行(灯真的亮/灭)
        → 回传(控制器发回状态)→ 图标更新(小程序确认)
半路上可能发生:
    排队(断网时在网络段等待)、丢失(丢包)、
    过期(排队超过 25 个周期作废)、被拒(访客开灯没权限)。
中间面板会实时显示最近一条指令走到了哪一步,日志区有完整记录。

----------------------------------------------
六、建议的四个小实验
----------------------------------------------
实验1 正常控制:导入「教材示例:客厅一盏灯」,点「开始」再点手机上的
      「客厅灯」,用「单步」逐跳观察:指令走到控制器灯才亮,
      回传走回小程序图标才变。想一想:为什么图标不是点完立刻变?
实验2 断网与丢包:导入「网络糟糕的雨天」,连发几条指令数丢了几条;
      再勾上「断网」发一条指令,看它排队变灰,马上恢复网络 vs
      等 25 个周期后才恢复,结果有什么不同?重点观察:回传丢失后,
      灯亮着、手机图标却是关的,房间里出现"⚠不一致"提醒。
实验3 权限校验:切换到「访客」账号点开灯——指令走到物联网平台就被
      拒绝,并回传"被拒"通知;再试试访客关灯(可以成功)。
      想一想:为什么智能家居要区分家人和访客的权限?
实验4 防抖与规则:先关掉「防抖」,对同一个按钮快速连点 3 下,
      看灯开→关→开地闪烁;再打开防抖重试,只有第一下有效。
      最后导入「天黑自动开灯规则」场景,点「开始」看平台自动开灯,
      再把光照拖高、勾选「天亮自动关所有灯」,看灯自动熄灭。

----------------------------------------------
七、常见问题排查
----------------------------------------------
1. 双击 .py 文件没反应,或打开的是记事本?
   → 电脑可能没装 Python。到 python.org 下载安装包,安装时务必勾选
     "Add Python to PATH",并保持默认勾选 tcl/tk 组件(Tkinter)。
     已装 Python 的,右键文件 → 打开方式 → 选择 Python。

2. 提示 "No module named tkinter" 或 "_tkinter"?
   → 安装 Python 时没有安装 tcl/tk 组件。重新运行 Python 安装包,
     选择 Modify(修改),勾选 "tcl/tk and IDLE" 后完成安装。

3. 点了手机上的灯按钮,灯一直不亮?
   → 依次检查:是不是没点「开始」(时间不流动,指令圆点不会走)?
     是不是勾了「断网」(圆点变灰在排队)?丢包率是不是调得很高
     (圆点变红丢失)?是不是用「访客」账号开灯(平台拒绝,日志里
     有"被拒"记录)?是不是防抖忽略了你的连点(日志里有提示)?

4. 灯明明亮了,手机上的图标却还是"关"?
   → 这正是本课要观察的现象:状态回传在网络里丢失了!
     日志里会有"⚠ 状态回传丢失"的记录,房间里会显示
     "⚠ 与手机图标不一致"。再发一次指令或降低丢包率即可恢复一致。

5. 勾了"天黑自动开客厅灯",灯却没有自动亮?
   → 检查:环境光照是否已拖到 30% 以下?模拟是否在运行(要点
     「开始」或「单步」)?客厅灯是否本来就亮着(规则只在灯灭时触发)?
     刚触发过一次的规则有 15 个周期的冷却时间,稍等片刻。

6. 窗口打开了,但界面文字是方块或乱码?
   → 系统缺少中文字体。Windows 一般自带微软雅黑不会出现此问题;
     如出现,请在系统设置中确认已启用中文语言与字体。

7. 命令行运行提示 "python 不是内部或外部命令"?
   → Python 没有加入 PATH。可改用命令 py 运行,或重新安装 Python
     并勾选 "Add Python to PATH"。

8. 导出按钮点了,文件在哪里?
   → 在「智能家居控制与规则模拟器.py」所在的文件夹里,文件名形如
     "家居控制日志_20260724_153000.csv"。每次导出都生成新文件,
     不会覆盖旧文件。若程序放在只读位置(如光盘),请先把整个
     文件夹复制到桌面再运行。

9. 导入示例场景时提示"导入失败"?
   → 请确认选择的是本文件夹里的「示例数据_家居场景.json」,
     且文件没有被改坏(可重新复制一份)。自己编写场景时,注意
     JSON 里必须有「场景列表」数组。

10. 程序运行久了会不会卡?关窗口会不会有残留?
   → 不会。日志超过一定条数会自动滚动清理;关闭窗口时程序会
     正确取消所有定时任务,不在后台常驻。
