==============================================
 本地消息发送接收模拟器(发布订阅实验器) · 使用说明
==============================================
配套教材:清华大学出版社《信息科技》五年级下册
          第2单元 第3课《智能种植项目设计——信息的发送与接收》(教材 P62—70)
适用对象:小学五年级学生与信息科技教师
运行环境:Windows 7/10/11,安装 Python 3.8 及以上(自带 Tkinter),
          完全离线运行,不需要联网,不需要安装任何第三方库。

----------------------------------------------
一、这个工具是做什么的?
----------------------------------------------
它在电脑上模拟一个"智能种植大棚"里的消息发送与接收系统
(物联网里常用的"发布/订阅"方式):
    左边 3 个发送端:温度 / 湿度 / 光照传感器,定时把读数
        "发布"到自己选择的主题(Topic)上;
    中间 1 个消息服务器:显示订阅表和消息队列,把每条消息
        按主题"路由"给所有订阅了该主题的接收端;
    右边 3 个接收端:显示屏 / 水泵 / 补光灯,各自"订阅"一个主题,
        只有主题一模一样才能收到消息并执行动作。
你能亲眼看到三个核心现象:
    1. 主题匹配才能收到(写错一个字母就"无人订阅");
    2. 一个主题可以有多个订阅者,一条消息广播给每一个订阅者;
    3. ACK 确认开启时,丢失的消息会超时自动重发。

----------------------------------------------
二、运行方法
----------------------------------------------
方法1(推荐,双击运行):
  1. 确认电脑已安装 Python(见"常见问题"第1条);
  2. 双击「本地消息发送接收模拟器.py」即可打开窗口。
     若双击打开的是记事本,请右键该文件 → 打开方式 →
     选择「Python」(或 Python Launcher)。

方法2(命令行运行):
  1. 按 Win + R,输入 cmd,回车打开命令提示符;
  2. 输入(注意路径里有中文,建议直接把文件拖进命令行窗口):
         python "本地消息发送接收模拟器.py"
     若提示找不到 python,可尝试输入 py 代替 python。

----------------------------------------------
三、界面分区说明
----------------------------------------------
① 场景区(左上)
   - 左侧三个彩色方框是发送端,显示当前读数和"发布→主题";
     主题下方文字变红,表示这个主题目前没人订阅;
   - 中间大方框是消息服务器:上半部分是"订阅表"(路由的依据),
     下半部分是"消息队列"(最近收到的消息);
   - 右侧三个方框是接收端,显示"订阅←主题"、最近收到的内容
     和执行动作(显示屏显示读数、水泵浇水、补光灯亮起);
   - 彩色圆点 = 传输中的消息(红色圆点来自温度传感器、蓝色来自
     湿度传感器、橙色来自光照传感器),圆点上方标着消息编号和主题;
   - 绿色小点 = ACK 确认回执(往回走);
   - 红色 ✕ = 消息在半路丢失;服务器里红点 + "无人订阅" =
     该主题没有任何接收端订阅,消息被丢弃;
   - 标着"(重发)"的圆点 = ACK 超时后补发的消息。

② 配置区(右上):改完立即生效。
   - 发布主题:为每个发送端选择往哪个主题发消息;
   - 订阅主题:为每个接收端选择只收哪个主题(可选"(不订阅)");
     注意下拉框里混有拼写很像的干扰项(如 farm/temp 和 farm/tmep),
     选错一个字母消息就送不到!
   - 消息格式:勾选"含单位"消息带上 ℃/%/lx,勾选"含时间"再加上
     模拟时刻,如 [08:15] 24℃;
   - 发送间隔滑块:每隔几个周期自动发一条(三个发送端错开发送);
   - 丢包率滑块:消息在每段路程中丢失的概率;
   - ACK确认开关:开启后收到消息会回执(绿色小点),丢失的消息
     等不到回执,超时 4 个周期自动重发,同一段最多重发 2 次。

③ 运行控制区(右中):开始 / 暂停 / 单步 / 重置 / 手动发一条。

④ 状态与日志区(下方):
   - 状态栏:模拟时间(1周期=1分钟)、在途消息数、等待重发数等;
   - 滚动日志:每条消息的完整生命周期,不同阶段不同颜色:
       发布 → 入队 → 路由 → 送达 / 无人订阅 / 丢失 / 重发,
     还会记录每一次调参,方便对照"改了什么 → 发生了什么"。

⑤ 结果区(右下):
   - 统计:发布数 / 送达数 / 无人接收数 / 丢失数 / 重发数;
   - 四个按钮:导出日志CSV / 导出方案TXT / 导入方案JSON / 帮助。

----------------------------------------------
四、每个按钮与参数的含义
----------------------------------------------
▶ 开始         让模拟时间流动,每 0.5 秒推进一个周期(模拟1分钟)。
⏸ 暂停         暂停时间流动,所有状态保持不变。
⏭ 单步         先暂停,再只推进一个周期。想看清一条消息怎么
               走完"发布→入队→路由→送达",就连续点它。
🔄 重置         清空在途消息、队列和统计,读数复位。
               主题配置、参数和日志保留,方便对比实验。
✉ 手动发一条   先在左边下拉框选一个发送端,点按钮立即发布一条
               消息(暂停时也能发,但要点「开始」或「单步」才走)。
📥 导出日志CSV  把全部日志存成 CSV 表格(Excel 可直接打开),
               文件保存在本程序所在文件夹,文件名自动加时间戳。
📄 导出方案TXT  把当前的发布/订阅配置、参数、统计和思考题
               生成一份"我的消息方案",可打印后手写完成。
📂 导入方案JSON 读入「示例数据_消息方案.json」,内含三组方案:
               教材示例:温湿度大棚 / 主题写错了(排错练习) /
               多订阅者广播,选一组即可载入。
❓ 帮助         弹出快速帮助窗口。

统计口径:
   发布数     发送端发布的消息条数(手动+自动,不含重发);
   送达数     接收端每成功收到一份 +1(一条消息广播给 3 个
              订阅者时,送达数 +3);
   无人接收数 到了服务器却没有任何订阅者的消息条数;
   丢失数     消息在网络中丢失的次数(重发后又丢会再计一次;
              重发成功的消息最终仍会计入送达数);
   重发数     因 ACK 超时而补发的次数。

----------------------------------------------
五、三个小实验建议(课堂/家庭均可)
----------------------------------------------
实验1:主题匹配与广播
  1. 点「导入方案JSON」载入「教材示例:温湿度大棚」,点「开始」;
  2. 用「单步」追踪一条消息:发布 → 入队 → 路由 → 送达,
     对照日志把每个阶段找出来;
  3. 再载入「多订阅者广播」:三个接收端都订阅 farm/temp,
     观察一条温度消息被复制成三份分头送达——发布数+1、送达数+3。

实验2:写错主题排错
  1. 载入「主题写错了(排错练习)」,点「开始」;
  2. 观察温度消息到服务器后变红提示"无人订阅",显示屏一直
     收不到温度,"无人接收数"不断增加;
  3. 当一回工程师:对照服务器订阅表,找出写错的主题
     (farm/tmep 应为 farm/temp),在配置区改正;
  4. 改好后继续运行,确认显示屏重新收到温度,统计里
     "送达数"恢复增长。体会:主题必须一字不差!

实验3:丢包与 ACK 重发
  1. 载入「教材示例」,把丢包率调到 40%,先取消勾选「ACK确认」;
  2. 点「开始」跑一会儿:红色 ✕ 表示消息半路丢失,日志写着
     "发送方不知道丢了,不会重发"——丢失数上涨,送达数变少;
  3. 勾选「ACK确认」再跑:同样会丢,但日志出现"ACK 超时…重发",
     标着"(重发)"的圆点补发上路,大部分消息最终还是送到了;
  4. 对比两次的 丢失数 / 重发数 / 送达数,点「导出方案TXT」
     把结论写进"我的思考"。

----------------------------------------------
六、常见问题排查
----------------------------------------------
1. 双击 .py 文件没反应,或打开的是记事本?
   → 电脑可能没装 Python。到 python.org 下载安装包,安装时务必勾选
     "Add Python to PATH",并保持默认勾选 tcl/tk 组件(Tkinter)。
     已装 Python 的,右键文件 → 打开方式 → 选择 Python。

2. 提示 "No module named tkinter" 或 "_tkinter"?
   → 安装 Python 时没有安装 tcl/tk 组件。重新运行 Python 安装包,
     选择 Modify(修改),勾选 "tcl/tk and IDLE" 后完成安装。

3. 点了「开始」,接收端却一直收不到消息?
   → 按顺序检查:发送端的发布主题和接收端的订阅主题是不是
     一字不差(小心 farm/tmep 这类干扰项)?接收端是不是选了
     "(不订阅)"?丢包率是不是调得很高?看服务器订阅表和
     日志里的"无人订阅"提示,最容易找到原因。

4. 明明开了 ACK,为什么还有消息永远丢了?
   → 同一段路程最多重发 2 次,若连续 3 次都被丢包(丢包率高时
     会发生),日志会写"已达最大重发次数,放弃"。把丢包率调低
     一点,或多观察几条消息即可看到重发成功的例子。

5. 命令行运行提示 "python 不是内部或外部命令"?
   → Python 没有加入 PATH。可改用命令 py 运行,或重新安装 Python
     并勾选 "Add Python to PATH"。

6. 导出按钮点了,文件在哪里?
   → 在「本地消息发送接收模拟器.py」所在的文件夹里,文件名形如
     "消息模拟器日志_20260724_153000.csv"。每次导出都生成新文件,
     不会覆盖旧文件。若程序放在只读位置(如光盘),请先把整个
     文件夹复制到桌面再运行。

7. 导入方案时提示"导入失败"?
   → 请确认选择的是本文件夹里的「示例数据_消息方案.json」,
     且文件没有被改坏(可重新复制一份)。自己编写方案时,注意
     JSON 里必须有「方案列表」数组,发送端/接收端名称要和
     程序里的完全一致。

8. 窗口文字是方块或乱码?
   → 系统缺少中文字体。Windows 一般自带微软雅黑不会出现此问题;
     如出现,请在系统设置中确认已启用中文语言与字体。

9. 程序运行久了会不会卡?关窗口后会不会有残留?
   → 不会。日志超过一定条数会自动滚动清理;程序用 root.after()
     驱动、不用线程,关闭窗口时会正确取消所有定时任务,
     不会在后台残留进程。

----------------------------------------------
七、数据与隐私
----------------------------------------------
本工具完全本地模拟,不使用真实网络:不联网、不采集、不上传任何数据;
所有导出文件都只保存在你自己的电脑上,可随时删除。
